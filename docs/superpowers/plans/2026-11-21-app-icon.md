# App Icon (藏 on a lotus throne) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the flat PNG icon with a layered Icon Composer icon: 藏 above a small lotus throne, with good light, dark and tinted appearances.

**Architecture:** A Python generator writes `DzzReader/AppIcon.icon` (icon.json + SVG layers). The 藏 outline comes from a Swift/CoreText helper that prints the glyph as an SVG path. `ictool` renders every appearance for checking; Xcode compiles the `.icon` as the app icon.

**Tech Stack:** Python 3 (stdlib only), Swift + CoreText (glyph helper), Icon Composer `.icon` format, `ictool`, XcodeGen.

**Spec:** `docs/superpowers/specs/2026-11-21-app-icon-design.md`

## Global Constraints

- Layout is **pedestal**: 藏 above a small lotus; the lotus must not cover any stroke of 藏.
- 藏 is the Songti SC Bold outline (`STSongti-SC-Bold`), about 40% of the canvas height (prototype: 560 pt outline at scale 0.72), above centre.
- Light: 藏 `#4A3426` on a sepia vertical gradient; dark: ivory 藏 on a deep brown-black gradient.
- Tinted: 藏 must be the brightest, clearest element.
- The icon is named `AppIcon`; `ASSETCATALOG_COMPILER_APPICON_NAME` stays `AppIcon`; the old `AppIcon.appiconset` is removed.
- Scripts run with `python3 -I`; files written with the Write tool (bash 3.2 heredoc limits).

## Review Focus

- Small size (60 pt): 藏 stays legible and the lotus reads as a lotus, not a pink smudge — checked in a 120 px render.
- TintedLight as well as TintedDark: 藏 must not vanish against a light tint — checked in both renders.
- Clear (glass) appearance: the icon must not become an unreadable blur — checked in ClearLight/ClearDark renders.
- Xcode actually picks up the `.icon` (not a stale cached icon) — checked by reading the built app's `Assets.car` / Info.plist icon name and the simulator home screen.
- Regeneration is reproducible: running the generator twice produces identical files — checked with `git diff --exit-code` after a rerun.
